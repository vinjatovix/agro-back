# 1. PURPOSE

This document defines the stable architectural specification of AgroApp.

It is the single source of truth for system architecture and evolves strictly through versioned increments.

---

# 2. SYSTEM OVERVIEW

AgroApp is a domain-driven backend system focused on agricultural modeling.

Core bounded contexts:

- Plant domain
- Bed domain
- Spatial system
- Query system
- API layer
- Validation & error system
- Persistence layer
- Shared utilities layer

---

# 3. ARCHITECTURAL RULES

## 3.1 Specification Evolution and Versioning Rule

Specifications evolve alongside the codebase. To prevent repository clutter, we maintain only the active living specification version. All historical versions, audits, and traceabilities are managed natively via the repository's Git history and tags rather than preserving legacy duplicated `.md` files.

---

## 3.2 Separation of concerns

The system is divided into:

- Domain (pure business logic)
- Application (use cases)
- Infrastructure (persistence, external systems)
- API layer (transport)
- Validation layer (input integrity)
- Query layer
- Shared utilities layer
- Documentation layer (OpenAPI)

---

## 3.3 Traceability rule

Every change MUST be traceable to:

- spec version
- roadmap iteration / spec module
- changelog entry

---

## 3.4 Contract enforcement rule

All external behavior (API responses, validation errors, query parsing, and status codes) MUST be consistent with the OpenAPI contract when defined.

OpenAPI takes precedence for external API behavior.
