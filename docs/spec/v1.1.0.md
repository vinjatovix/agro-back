# 1. PURPOSE

This document defines the stable architectural specification of AgroApp.

It is the single source of truth for system architecture and evolves strictly through versioned increments.

---

# 2. SYSTEM OVERVIEW

AgroApp is a domain-driven backend system focused on agricultural modeling.

Core bounded contexts:

- Plant domain
- Bed domain
- Spatial system
- Query system (NEW)
- API layer
- Validation & error system
- Persistence layer
- Shared utilities layer (NEW)

---

# 3. ARCHITECTURAL RULES

## 3.1 Immutability rule

Once a spec version is published:

- it MUST NOT be modified
- any change requires a new version (v1.2.0, etc.)

---

## 3.2 Separation of concerns

The system is divided into:

- Domain (pure business logic)
- Application (use cases)
- Infrastructure (persistence, external systems)
- API layer (transport)
- Validation layer (input integrity)
- Query layer (NEW)
- Shared utilities layer (NEW)
- Documentation layer (OpenAPI)

---

## 3.3 Traceability rule

Every change MUST be traceable to:

- spec version
- epic module
- changelog entry

---

## 3.4 Contract enforcement rule

All external behavior (API responses, validation errors, query parsing, and status codes) MUST be consistent with the OpenAPI contract when defined.

OpenAPI takes precedence for external API behavior.

## EPIC 16 — QUERY SYSTEM FOUNDATION (NEW)

status: active

### Scope

Introduces standardized query parsing:

- GenericQueryParser
- QueryParserUtils
- filter operators:
  - eq
  - has / hasAny
  - contains
  - startsWith / endsWith
  - gt / gte / lt / lte

- pagination normalization
- CSV-based query decoding
- strict type coercion rules

### Contract rules

- invalid filters are ignored or rejected depending on context
- numeric coercion is mandatory for comparison operators
- array-based operators must normalize CSV inputs
- query parsing MUST be deterministic

---

## EPIC 17 — SHARED UTILITIES LAYER (NEW)

status: active

### Scope

Reusable utilities used across layers:

- DTO utilities:
  - deepMerge
  - buildPatch

- interpolation system: (testing)
  - route interpolation
  - JSON interpolation

- comparison utilities: (test contracts)
  - deep response comparison

- JSON parsing safety utilities

### Rules

- utilities must be framework-agnostic
- no domain logic inside shared utilities
- deterministic behavior required for test reproducibility
